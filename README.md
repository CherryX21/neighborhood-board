# Дошка оголошень

Програмування веб-застосувань, практичні роботи.

Проєкт: neighborhood-board (варіант 18).

Поточний етап: практична робота №15 — аудит безпеки клієнтського застосунку (розділ «Безпека» нижче). Попередній етап: №14 — власний сервер Node.js (Express) у теці server/, який роздає файли клієнта та віддає оголошення через GET/POST /api/posts (ще раніше: №13 — SPA з hash-маршрутизацією, №12 — CSS-анімація нового оголошення, №11 — IndexedDB, №10 — Vue 3, №9 — клієнт для API).

## Запуск

```bash
cd server
npm install
npm start
```

Після запуску сторінка доступна за адресою http://localhost:3000. Сторінку потрібно відкривати саме з цього сервера: запит до API відносний (`/api/posts`), тому Live Server без Node-сервера оголошень не отримає.

Інший порт: `PORT=3001 npm start`. Режим із автоперезапуском: `npm run dev`.

## API

| Метод | Адреса | Відповідь |
| :--- | :--- | :--- |
| GET | /api/posts | 200, масив оголошень |
| GET | /api/posts/:id | 200, одне оголошення, або 404 |
| POST | /api/posts | 201 і створене оголошення, або 400/413 |

## Безпека (практична робота №15)

Аудит проводився для варіанта 18: вектор XSS — поле `description` оголошення, дані — сховище `posts`.

**Що перевірено й знайдено**

- XSS через `innerHTML`: небезпечних місць немає. У коді (js/, index.html, server/) відсутні `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `v-html` та `eval`. Дані користувача й API виводяться лише інтерполяцією Vue `{{ }}` або через `textContent`, тобто як текст, а не як розмітка. Вразливий `innerHTML` практикуму №7 було прибрано під час переходу на Vue (практична робота №10).
- Контрольний експеримент: якщо тимчасово замінити в AdCard `{{ description }}` на `v-html="description"`, рядок `<img src=x onerror="alert('XSS')">` виконується. З поверненням до `{{ description }}` він показується як звичайний текст. Цей експеримент у репозиторій не потрапляє.
- Перевірені шляхи введення: форма (через IndexedDB), `POST /api/posts`, адресний рядок (hash-маршрути), підроблений запис безпосередньо в IndexedDB. Жоден XSS-рядок не виконується.
- Сховища: IndexedDB `NeighborhoodBoardDB` → `posts` містить лише публічні поля оголошення (`id`, `title`, `category`, `price`, `description`, `date`); localStorage, sessionStorage і cookie порожні. Чутливих даних (паролі, токени, персональні дані) немає.
- Секрети: ключів, паролів і токенів у коді та даних немає (`.env` додано до `.gitignore` на майбутнє).

**Що виправлено**

- Vue 3.5.13 більше не завантажується зі стороннього CDN без перевірки цілісності, а лежить у `js/vendor/vue.global.prod.js` (SHA-256 `c459ba7cc8db65c982589fa5d64c7ff478877e8e5b0fd75683207cec6a4e89e8`). Сторонній скрипт має доступ до всіх даних сторінки та її сховищ.
- Сервер додає заголовки безпеки: `Content-Security-Policy` (скрипти лише з власного origin: inline-обробник на кшталт `onerror` не виконується навіть за помилково доданого `v-html`), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`.

**Відомі обмеження**

- `script-src` містить `'unsafe-eval'`: Vue у глобальній збірці компілює шаблони під час виконання. Позбутися цього можна лише попередньою компіляцією шаблонів.
- CSP діє, коли сторінку віддає Node-сервер; зі статичного хостингу (наприклад, GitHub Pages) заголовків немає.
- `POST /api/posts` не має автентифікації та обмеження кількості записів; сервер слухає лише `127.0.0.1` і зберігає дані в пам'яті.
- Шрифти Plus Jakarta Sans підключаються з Google Fonts (дозволено в CSP за доменом).
- HTTPS: локально застосунок працює за HTTP на `localhost` (безпечний контекст). Для публічного розгортання потрібен хостинг із HTTPS за замовчуванням; GitHub Pages віддає лише статику, тож API з практичної роботи №14 вимагає окремого Node-хостингу.
